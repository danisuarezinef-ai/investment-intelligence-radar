# PRE-1.6 Tasks 131–150 — Decision-time provenance hardening

Scope: backend / Cloud / PAPER / SHADOW only. Windows remains 1.5.28. `REAL_TRADING=false` is mandatory. No task in this block may release Setup, promote/demote automatically, or submit a real order.

| Task | Control | Acceptance condition |
|---|---|---|
| 131 | Transactional provenance store | Local immutable PAPER decision-envelope table exists. |
| 132 | Challenger BUY capture | BUY trade and provenance envelope are committed in the same SQLite transaction. |
| 133 | Challenger SELL capture | SELL trade and provenance envelope are committed in the same SQLite transaction. |
| 134 | Champion BUY capture | Champion BUY and provenance envelope share one transaction/timestamp. |
| 135 | Champion SELL capture | Champion SELL and provenance envelope share one transaction/timestamp. |
| 136 | Strategy version | Exact decision configuration is content-addressed at decision time; no guessed version. |
| 137 | Provider PIT | Provider/price snapshot uses only rows timestamped `<= trade_ts`. |
| 138 | Regime PIT | Regime snapshot uses only rows timestamped `<= trade_ts`. |
| 139 | Benchmark PIT | Entry benchmark vector freezes only prices available at decision time. |
| 140 | Cost provenance | Fees, spread and FX assumptions are frozen explicitly where available. |
| 141 | Entry-only linkage | Closed outcomes link to BUY envelope by competitor + symbol + entry timestamp, never exit fields. |
| 142 | Trace audit | Prospective closes report matched/missing/version/lookahead/collision diagnostics. |
| 143 | Exact source precedence | Transactional local envelope is preferred over any later ledger reconstruction. |
| 144 | Legacy fallback | Any ledger-derived envelope is explicitly labelled reconstructed/fallback and remains a blocker. |
| 145 | PAPER checkpoint v2 | Exact engine checkpoint includes local provenance table. |
| 146 | Schema migration | Existing schema-v1 checkpoint restores exactly, then upgrades to v2 without fabricating provenance. |
| 147 | Checkpoint Edge compatibility | Private Edge authority accepts/rehydrates schema 1 and 2 only. |
| 148 | Remote immutability | Hardening authority inserts first envelope per origin/source/trade and never rewrites it. |
| 149 | Full CI | Compile, full pytest suite, debt audit and integrity audit all succeed on exact head. |
| 150 | Production proof | Schema-v2 survives a production redeploy exactly; natural PAPER decisions produce transactional envelopes. If no natural trade occurs, remain evidence-pending rather than force/backfill one. |

## Fail-closed rules

- No future/exit field may participate in entry-envelope creation or entry linkage.
- No historical trade receives an invented strategy version.
- No synthetic production trade may be created merely to satisfy task 150.
- Any immutable-envelope collision or checkpoint hash mismatch fails closed.
- Missing provenance is evidence pending, never treated as neutral/good evidence.
- `REAL_TRADING` remains `false` in code, persistence, endpoints and authority records.
