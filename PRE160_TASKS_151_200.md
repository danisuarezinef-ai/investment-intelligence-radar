# PRE-1.6 Tasks 151–200 — Reliability, evidence maturity, governance and release authority

Scope: backend / Cloud / PAPER / SHADOW only. Windows stays at **1.5.28**. No Setup is built by this block. `REAL_TRADING=false` is invariant. No automatic promotion, demotion, release or real order may be introduced.

State vocabulary: `PASS`, `PENDING_SAMPLE`, `PENDING_TIME`, `NOT_VERIFIED`, `FAILED`. A missing observation is never converted to a neutral or positive score.

## A. Reliability, SLO and sync backpressure — 151–160

| Task | Control | Acceptance condition |
|---:|---|---|
|151|Dual-sync SLO contract|Generic and learning sync expose explicit latency/retry/circuit semantics and no timeout-as-zero behavior.|
|152|Generic sync latency budget|Observed successful generic sync latency stays within the configured budget; otherwise readiness remains blocked.|
|153|Learning sync latency budget|Observed successful learning sync latency stays within the configured budget; otherwise readiness remains blocked.|
|154|Circuit-breaker recovery|Both sync paths expose consecutive failures, open-until and recovery counters; circuit-open is never interpreted as healthy.|
|155|Cursor-after-ack invariant|No sync cursor may advance before complete remote success.|
|156|Adaptive batch ceiling|Payload batches are bounded and can be reduced under degraded latency without increasing write authority.|
|157|Backpressure visibility|Health output distinguishes configured/healthy/degraded/circuit-open and reports last successful latency.|
|158|Retry de-synchronisation|Retries use bounded jitter/backoff to avoid a thundering herd after transient Supabase failures.|
|159|Fail-closed read surfaces|Operational endpoints may use stale cache with explicit `STALE_CACHE`, never fabricate zero evidence.|
|160|Production SLO audit|External CI validates both configured sync channels, safety boundary and health semantics.

## Non-negotiable invariants

- `REAL_TRADING=false` in runtime, persistence, health, audit and release authority.
- Windows remains `1.5.28` throughout this work package.
- No synthetic trade, artificial close, backfill or reconstruction may be created to make an evidence task pass.
- `PENDING_SAMPLE` and `PENDING_TIME` are successful fail-closed states when evidence is naturally immature.
- A timeout, missing row, provider gap or stale cache is never interpreted as evidence of zero risk or zero error.
- Release/promotion/demotion are review decisions outside this authority layer; all automatic action flags remain false.
